SEATTLE PUBLIC SCHOOLS SCHOOL EXPLORER
External CSV edition | Prepared October 13, 2026

PUBLISH TO GITHUB PAGES
1. Extract this ZIP.
2. Upload index.html, school_profiles.csv and p223_enrollment.csv into the SAME
   folder of your GitHub repository, replacing the older index.html.
3. Keep your Pages source set to main / (root), or whichever folder already
   hosts your site. Commit the files; Pages republishes the site.
4. The dashboard reads both CSVs on page load. It does not contain a fallback
   copy of school statistics. Leave both CSVs publicly accessible beside it.
5. Open the published HTTPS URL. Opening index.html directly from disk will
   show instructions because browsers restrict fetching adjacent local files.
   Optional local test: run python3 -m http.server 8000 in this folder, then
   open http://localhost:8000 in your browser.

WHAT EACH FILE HOLDS
school_profiles.csv: 106 rows, 66 columns. One row per directory school/program
plus Bridges Transition. Principals, location, annual student demographics,
teacher actuals, staffing budgets, historical facility measurements and checks.
These fields update at different intervals. Their reporting years remain in
column names. This is not an immutable file or a single-year dataset.

p223_enrollment.csv: 106 rows, 109 columns. One current monthly snapshot, one row
per school/program. Grade-level and total population, regular program, special
education, bilingual services, gender totals, state-funded head count/FTE,
report dates, source URL and monthly coverage notes. Currently September 2026.

index.html: Presentation, field definitions, source register and CSV loader.
School statistics are fetched from the two files above, not embedded in HTML.
No external JavaScript libraries or build step are required.

Both CSVs repeat school_key and school_name. Only school_key is used to join.
The profile school_name is the display name; a name change does not break a join.
CSV records use UTF-8 with BOM, comma separators and standard quoted fields.
The joined dashboard exposes 173 distinct columns: the original 167 columns
(with month-neutral P223 names) plus six monthly metadata fields.

MONTHLY ENROLLMENT UPDATES
1. Retrieve the next official report from:
   https://www.seattleschools.org/departments/dots/data-reporting/enrollment-reporting-p223/
2. Save a copy of the previous p223_enrollment.csv elsewhere as an archive,
   for example in a history/ folder named p223_2026-09.csv. The current dashboard
   reads ONLY the fixed filename p223_enrollment.csv; it does not read archives.
3. Replace its rows with the new monthly figures, keeping headers and school_key
   unchanged. Each school may appear at most once. Do not append different months
   into the current snapshot file. New schools need a school_profiles.csv row too.
4. Update p223_reporting_month (YYYY-MM), p223_school_year,
   p223_report_created_date, p223_source_url and p223_retrieved_date.
   Set p223_count_date_grades_1_12 and p223_count_date_preschool_k to the actual
   dates in the report, even if those dates differ. Refresh school page references,
   p223_coverage_status and p223_notes as well.
5. For a school with an available table, use p223_coverage_status = Matched.
   Update all school totals, grade totals, gender counts, K-12 total and
   grades_with_students. Preserve the distinction between head counts and FTE.
6. For a school not separately reported, leave count fields blank and describe
   the gap in p223_coverage_status. Its row may also be omitted; the school profile
   still appears and the dashboard explicitly shows missing enrollment.
7. Publish the replaced CSV. Refresh the page to load the new figures, dates,
   report label and source URL. No HTML edits are required for the monthly update.
   Normal GitHub Pages publication/caching delays still apply.

PROFILE / ANNUAL UPDATES
Edit school_profiles.csv to update principal names, addresses, corrections or
values within their labeled reporting periods. Update snapshot_date and related
checks/notes when verifying the changed record. Changes appear on the next load.
Do not put a newer year's teacher, demographic, budget or facility figures in
columns labeled with an older year. A rollover of annual reporting years requires
updating the column schema, labels and source definitions in index.html together.

VALIDATION AND MISSING VALUES
- Duplicate keys, unknown enrollment keys, mixed months, missing required
  headers, malformed CSV, non-numeric counts and unreconciled enrollment totals
  produce a visible error instead of silently displaying incorrect data.
- Missing values are empty cells, not NA or guessed zeros.
- Blank grade rows INSIDE an available report are confirmed zeros. An unavailable
  school report is never zero population.
- Counts in each grade must sum to the reported school totals. Male + female +
  non-binary must equal the published student count. K-12 excludes preschool.
- Bilingual and special education groups overlap; do not sum them as distinct
  student categories. Funding head count/FTE may differ from total students.
- Historical teacher ratios and annual demographics are not recalculated with
  the newer monthly enrollment. Keep their measurement years visible.
- A school's source PDF page is the physical PDF page including cover/contents.
- Five other P223 reporting units are not roster school rows. School CSV totals
  alone do not represent all district reporting units. The original source report
  and initial validation document retain the district reconciliation.

VERIFICATION OF THIS EDITION
All original numeric, identity and source values were preserved when splitting.
106 school keys align across both CSVs. Interaction checks exercised every school,
all 173 joined fields, missing rows, malformed files and a changed monthly CSV.
A changed month/source label and changed principal were tested without editing
HTML. Browser rendering was not re-tested in this environment; the existing
responsive page design was retained. Validation runs in the browser on each load.

The remainder of this guide documents each CSV header and its original source.
The same field definitions and links are available in the dashboard.
